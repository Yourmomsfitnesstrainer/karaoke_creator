## Purpose & Scope
Оценка канонических JSON на локальном размеченном корпусе для выбора уточнителя. Визуальная ошибка MP4 оценивается отдельно.

## Surface
- Метрики и критерии приёмки: @src/karaoke_generator/evaluation.py.
- Запуск вариантов уточнения: @scripts/benchmark_timing.py.
- Формат локального корпуса и команды: @docs/timing-evaluation.md.

## Normative Behavior
1. WHEN evaluator получает JSON, evaluator MUST использовать канонические границы без offset.
2. WHEN evaluator считает квантили, evaluator MUST применять nearest-rank.
3. IF граница отсутствует или невалидна, THEN evaluator MUST учитывать бесконечную абсолютную ошибку.
4. WHEN evaluator считает общий результат, evaluator MUST включать валидный fallback.
5. WHEN evaluator считает signed bias, evaluator MUST использовать конечные предсказания и публиковать их число.
6. WHEN evaluator создаёт отчёт, evaluator MUST публиковать покрытие, результаты песен и отмеченных сложных случаев.
7. WHEN runner сравнивает уточнители, runner MUST повторно использовать зафиксированную ASR-сетку и WAV.
8. WHEN runner запускает вариант, runner MUST проверить хеш WAV против сохранённого ASR.
9. WHEN runner создаёт отчёт, runner MUST сохранить хеш корпуса, входов, модели, версии, настройки и время запуска.

## Constraints & Invariants
- Песни распределяются между tuning и acceptance до настройки параметров; идентификаторы песен уникальны.
- Эталон фиксирует индекс слова в полном TXT, абсолютные start/end, неопределённость разметки и однозначность конца.
- Минимум корпуса: 5 песен, 15 фрагментов по 20–40 секунд, 500 слов; acceptance содержит минимум 3 песни и 300 слов.
- Пороги начала: медиана ≤80 мс, P90 ≤150 мс, доля ошибок >250 мс ≤2%, абсолютная медиана signed error ≤40 мс.
- P90 однозначных концов ≤200 мс; P90 отдельной песни не ухудшается более чем на 20 мс.
- Если исходный P90 выше 150 мс, требуется снижение минимум на 30%; иначе сохраняется исходный P90.
- Бесконечные ошибки сериализуются как null с отдельным статусом слова; они не исключаются из знаменателя.
- Corpus и baseline предоставляет пользователь. Автоматического выбора рекомендованной модели без измерений нет.

## Failure Behavior
1. IF эталон содержит повторный индекс или невалидные границы, THEN evaluator MUST выдать ValueError.
2. IF неопределённость разметки отсутствует, THEN evaluator MUST выдать ValueError.
3. IF корпус меньше требований, THEN evaluator MUST вернуть insufficient_corpus.
4. IF baseline отсутствует, THEN runner MUST отметить приёмку как незапущенную.

## Conformance
@tests/test_evaluation.py проверяет бесконечные ошибки, покрытие, signed bias, fallback и регрессию отдельной песни.
Синтетические тесты не доказывают акустическую точность на вокале.
