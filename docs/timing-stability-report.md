# Проверка таймингов без эталонов

6 сентября 2026. Продолжение [первого этапа](word-timing-implementation-report.md). Ветка `improve/word-timing-accuracy`, основа `350088c`. Отчёт входит в фиксируемую версию.

По решению пользователя продолжаем проверять локальные песни без ручной разметки. Сохранён `output/timing-candidate-v1`: варианты для просмотра и будущих регрессионных сравнений. Статус `candidate`, `human_review=pending`, `ground_truth=false`. Понравившийся пользователю вариант станет контрольным после просмотра; машинный результат не объявляется правильным автоматически.

## Пользовательская проверка и фиксация версии

После самостоятельного запуска пользователь сообщил, что результат стал лучше и в целом устраивает, и попросил зафиксировать проект как есть. Две проблемы остаются открытыми:

1. **При обработке песни с музыкой заметная часть слов «съедается».** Это наблюдение пользователя о качестве обработки. Точные фрагменты, число потерянных слов и этап возникновения потерь не установлены. Возможное влияние разделения вокала и распознавания требует отдельной проверки; причина не считается доказанной. Наличие слова в TXT/JSON не равнозначно его успешному распознаванию или правильной привязке к вокалу.
2. **Подсветка иногда чуть не совпадает со словами.** Сохраняются локальные ранние или поздние границы. Пользователь считает общий результат приемлемым; акустическая ошибка его последнего запуска не измерена. Приведённые ниже дельты стресс-проверок не являются измерением этой пользовательской жалобы.

Решение — сохранить достигнутые улучшения и перечисленные ограничения без продолжения настройки алгоритма. Это принятие текущего состояния для коммита, а не подтверждение всех акустических порогов ТЗ. Конкретный файл из `timing-candidate-v1` пользователь эталоном не назначал, поэтому его манифест остаётся в статусе кандидата.

Две настоящие песни найдены в сохранённых заданиях Web UI. Для русского запуска взята полная песня и её очищенный TXT. Английский фрагмент — 14,5–44,4 с оригинала, строки 10–17 старого JSON при нумерации с нуля. Старые времена использованы только для выбора фрагмента; распознавание и уточнение выполнены заново. Исходные задания не изменялись.

Преобразования: 750 мс тишины перед записью, амплитуда ×0,5, две копии записи с паузой 1 с. ASR каждого исходника фиксирован; для преобразований его сетка переносится по известному смещению. Измеряется устойчивость уточнения и mapping, а не повторного ASR и не акустическая ошибка. Проверяются все слова, включая интерполяцию и приблизительное деление, сохранение текста, положительные интервалы и монотонность.

## Найденные и исправленные дефекты

1. **Пропуск подготовки входа Hugging Face.** В установленном WhisperX 3.8.6 processor использовался для словаря, а waveform передавался в модель без feature extractor. Обе проверенные русские модели задают `do_normalize=true`. Теперь каждое окно проходит штатный feature extractor; исходный звук и абсолютная шкала сохраняются. На коротком примере large максимальное изменение при уменьшении громкости снизилось со 181 до 20 мс. Для base с экспериментальным контекстом 0,6 с оно снизилось с 301 до 0 мс.
2. **Отказ из-за миллисекундного округления.** WhisperX округляет границы до 0,001 с; кандидат мог выйти за точное окно на долю миллисекунды и вызвать fallback на ASR с разницей 300 мс. Выход до 0,5 мс ограничивается точной границей с сохранением исходного кандидата и `rounding_clamp`. Больший выход отклоняется. На коротком русском примере large максимальное изменение после вставки тишины снизилось с 300 до 2 мс.
3. **Составное соответствие между блоками.** Короткое завершение предыдущего блока могло получить время первого слова следующего повтора. На настоящей русской песне это давало 32 492 мс изменения. Mapping теперь учитывает блоки TXT и запрещает составным соответствиям пересекать пустую строку. Конкретный перенос устранён; максимальное оставшееся изменение у base в проверке повтора — 316,816 мс.

Текущие версии алгоритмов: ASR 2, refinement 5, mapping 4. Новые уточнения пересчитываются; ASR-кеш сохраняется. Настройки модели по умолчанию не повышены до large: обе русские модели подготовлены для сравнения на слух.

Основание для подготовки входа: локальные `preprocessor_config.json`, исходник установленного WhisperX и [официальный feature extractor Transformers](https://github.com/huggingface/transformers/blob/main/src/transformers/models/wav2vec2/feature_extraction_wav2vec2.py). Описание нормализации: [Wav2Vec2 в Transformers](https://huggingface.co/docs/transformers/model_doc/wav2vec2).

## Итоговая устойчивость

В каждой ячейке: **максимальное изменение / P90, мс; число слов с изменением >40 мс**. Для слова берётся большая из абсолютных дельт начала и конца после вычитания известного смещения. Это не ошибка относительно пения. Повтор содержит вдвое больше слов.

| Материал и уточнитель, контекст 0,3 с | Тишина | Амплитуда ×0,5 | Повтор |
|---|---|---|---|
| Синтетический RU, base | 20 / 1; 0 из 45 | 21 / 0; 0 из 45 | 20,878 / 1,122; 0 из 90 |
| Синтетический RU, large | 2 / 1; 0 из 45 | 20 / 0; 0 из 45 | 226 / 1,122; 1 из 90 |
| Настоящий RU, base | 0 / 0; 0 из 179 | 0 / 0; 0 из 179 | 316,816 / 0,816; 9 из 358 |
| Настоящий RU, large | 0 / 0; 0 из 179 | 0 / 0; 0 из 179 | 322,184 / 0,816; 3 из 358 |
| Настоящий EN, torchaudio | 421 / 1; 2 из 90 | 20 / 0; 0 из 90 | 421 / 1; 6 из 180 |

У настоящей русской песни 176/179 слов сопоставлены с ASR: итоговые источники — 135 refined, 15 ASR, 26 approximate_split и 3 interpolated у обоих уточнителей. У английского фрагмента сопоставлены 88/90 слов: 78 refined, 4 ASR, 6 approximate_split, 2 interpolated. Эти доли описывают текстовое покрытие.

Остались отдельные выбросы при повторении и изменении контекста у краёв записи. Например, первый английский ASR-сегмент начинается слишком близко к нулю для полного контекста 0,3 с: вставка тишины добавляет 40 мс доступного контекста. У русского синтетического large последний интервал в первой копии повтора получает дополнительный контекст после прежнего конца файла. Такие случаи сохранены в отчётах, а не исключены из метрики. Высокий score сам по себе не доказывает правильный конец слова.

## Тесты, звук и просмотр

- Полный pytest: **65 тестов прошли**, два deprecation warning из Starlette/FastAPI/httpx.
- Семь fault probes выполнены в отдельных копиях кода: четыре с первого этапа и три новых. Новые проверки ловят пропуск нормализации, отказ от допуска округления и игнорирование границы блока. Перед дефектом и после восстановления тест проходит; с дефектом падает. Логи и diff — `output/timing-verification/probes/`.
- Полный generate на синтетическом рэпе: **55/55 слов** сопоставлены, интерполяции нет; реальные Demucs и FW medium отработали. Временная шкала суммы stem и MP4 подтверждена сравнением сигнала.
- В трёх контрольных видео с настоящим пением проверены подготовка звука, сумма stem и декодированное аудио MP4: везде `verified`. Кадры русского и английского видео просмотрены: текст читается и не обрезан. Акустическое совпадение на слух этими кадрами не оценивалось.

Окружение: macOS 26.5.2 arm64, Python 3.12.2, faster-whisper 1.2.1, WhisperX 3.8.6, CTranslate2 4.8.2, torch/torchaudio 2.8.0, Transformers 4.57.6, NumPy 2.5.2, Demucs 4.1.0, FFmpeg 9.0.1 и libass 0.17.5. ASR medium выполнялся на CPU, фактический compute type `int8_float32`; уточнители — CPU. Score floor 0,05 остаётся некалиброванным.

`output/` исключён из Git. Оригиналы сохранённых Web-заданий не перезаписаны. Новые веса русской large и английского уточнителя загружены в стандартные локальные кеши моделей. Все отчёты содержат детали по словам; утверждения о точности в миллисекундах относительно настоящего пения пока не делаются.

Для повторения проверки используйте [команду runner](timing-evaluation.md#работа-без-эталонов) с новой папкой результата. Следующая содержательная проверка — прослушать сохранённые варианты и отметить конкретные места, где подсветка мешает петь. После положительной оценки выбранный вариант можно использовать как контроль будущих изменений.
