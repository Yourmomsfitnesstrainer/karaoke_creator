# ТЗ v1 — локальный генератор karaoke MP4

Статус: подтверждено пользователем заранее 2026-09-03.

## Цель и аудитория

Создать локальный инструмент для владельца MacBook Pro на Apple Silicon, который получает аудиофайл и окончательный текст песни, автоматически синхронизирует каждое пользовательское слово с вокалом и создаёт готовое karaoke-видео MP4.

Продукт продаёт технологию обработки пользовательских файлов, не содержит каталога музыки, не скачивает треки или тексты и не публикует результаты.

Главный инвариант: `lyrics.txt` — единственный источник отображаемого текста. Распознавание речи может дать только временные метки и confidence; оно не вправе менять, исправлять, добавлять или удалять слова пользователя.

## Пользовательские сценарии

1. Пользователь выбирает MP3/WAV и UTF-8 TXT, запускает одну CLI-команду и получает `karaoke.mp4`, `karaoke.ass`, `alignment.json` и промежуточные файлы.
2. По умолчанию приложение пытается отделить вокал и использует instrumental в видео. При недоступности separation синхронизация продолжается по оригиналу, а режим аудио явно переключается на original с предупреждением.
3. Пользователь меняет оформление или вручную правит `alignment.json`, запускает только render и не повторяет ML-этапы.
4. Локальный Web UI предоставляет те же базовые действия: загрузить два файла, выбрать параметры, увидеть стадии, скачать артефакты.

## Входит в MVP

- Вход: MP3, WAV; через FFmpeg также FLAC, M4A, AAC и OGG.
- UTF-8, кириллица, латиница, смешанный текст, пустые строки как границы блоков.
- Сохранение регистра, `ё`, апострофов, дефисов и пунктуации в отображаемом тексте.
- Автоматические word-level timestamps с монотонным сопоставлением повторяющихся строк.
- Явная маркировка неуверенных и интерполированных слов.
- ASS с плавным `\kf`-эффектом, текущей и следующей строкой, переносом длинных строк без разрыва слов.
- 1080p H.264/AAC MP4 с оригинальным или инструментальным аудио.
- Фоны: встроенный анимированный градиент, сплошной цвет, пользовательская картинка или видео.
- Кеш тяжёлых стадий по хешу входов и значимых настроек.
- CLI, минимальный локальный Web UI, Docker и нативный macOS-запуск.
- Понятные логи, диагностическая команда и unit/integration smoke tests без обязательной ML-модели.

## Не входит в MVP

- Аккаунты, платежи, облако, публикация и каталог песен.
- Автоматический поиск, скачивание или сохранение музыки и полного текста песни.
- Мобильное приложение и production-хостинг.
- Фонемная/послоговая разметка и обещание студийной точности без ручной проверки.
- Полноценный визуальный редактор waveform; JSON остаётся редактируемым контрактом.

## Поведение и крайние случаи

- Текст токенизируется по пробелам; display-форма остаётся неизменной, для alignment хранится отдельная нормализованная форма.
- Распознанные слова сопоставляются с пользовательскими глобальным sequence alignment. Порядок времён строго не убывает, поэтому одинаковые строки не попадают в один момент.
- Не найденное слово остаётся в результате с `aligned=false`, `confidence=0` и временем, интерполированным между соседями (`alignment_source=interpolated`).
- Если нет ни одного распознанного слова, обычный generate завершается понятной ошибкой; явно выбранный диагностический backend `uniform` допускается только для smoke/demo.
- Строки, не помещающиеся в безопасную ширину, делятся на визуальные строки по словам.
- Рендер проверяет наличие FFmpeg с фильтром `ass`. На Homebrew приоритет имеет keg-only `ffmpeg-full`; обычный FFmpeg без libass отвергается с точной инструкцией.
- Любая стадия пишет атомарный артефакт; частичный `alignment.json` сохраняется, когда восстановление возможно.

## Данные, роли, приватность и интеграции

- Одна локальная роль: владелец файлов.
- Все входы, модели, кеш и результаты остаются на машине пользователя.
- Сеть нужна только при первоначальной установке пакетов/ML-моделей.
- Интеграции: локальные исполняемые `ffmpeg`/`ffprobe`, опциональные Python-пакеты `faster-whisper`, `whisperx`, `demucs`.
- Репозиторий создаётся приватным, если пользователь отдельно не запросил публичный.

## Критерии приёмки

Команда

```bash
karaoke-gen --audio song.mp3 --lyrics lyrics.txt --output result
```

без ручной переклейки создаёт открываемый `result/karaoke.mp4` с аудио и синхронной подсветкой слов, а также `karaoke.ass`, `alignment.json`, `processed_lyrics.txt` и метаданные кеша.

Дополнительно:

- все display-слова в JSON и ASS происходят только из `lyrics.txt`;
- repeated lines и timings монотонны;
- unit tests покрывают parser, нормализацию, кириллицу, пунктуацию, повторения, интерполяцию, ASS и перевод времени;
- smoke test создаёт MP4 без скачивания ML-модели;
- `karaoke-gen render --alignment ...` не запускает ASR/separation;
- на Apple Silicon нет обязательной CUDA-зависимости, CPU fallback документирован;
- Docker-образ содержит FFmpeg с libass, но Docker не является единственным способом запуска.

## Предположения, риски и открытые вопросы

- Автоматическая синхронизация музыки не гарантирует frame-perfect результат: адлибы, перекрывающиеся голоса и неверный/неполный текст требуют правки JSON. Архитектура это допускает без повторного ML-запуска.
- WhisperX официально поддерживает точные word timestamps, но его стандартный Mac-путь CPU/INT8; MPS не считается обязательным. Стандартный backend MVP — `faster-whisper` CPU/INT8, WhisperX — опциональный refinement/backend.
- Исходный Demucs больше активно не развивается; поэтому separator изолирован интерфейсом и по умолчанию может быть отключён. В будущем backend можно заменить на BS/MelBand-Roformer.
- Качество instrumental ниже исходной фонограммы и зависит от модели.
- Полный текст и аудио коммерческих песен пользователь обязан предоставить сам на законном основании. Тестовый репозиторий использует синтетический/public-domain материал.
- Открытый продуктовый вопрос после MVP: нужен ли встроенный waveform-редактор. Сейчас контрактом служит `alignment.json`.

## План реализации

- Python 3.11/3.12, пакет `karaoke_generator`, dataclasses/Pydantic-совместимый JSON.
- Независимые стадии: preprocess → optional separation → transcribe/align → interpolate → ASS → FFmpeg render.
- Backends: `faster-whisper` (default), `whisperx` (optional), `uniform` (explicit demo/test only).
- Рендер: FFmpeg `gradients`/background input + libass `ass` filter + H.264/AAC.
- CLI: стандартный `argparse` с командами generate/render/doctor/web; `karaoke-gen --audio ...` остаётся короткой формой generate.
- Web: FastAPI/uvicorn как optional extra поверх того же pipeline.
- Конфигурация: YAML с override из CLI, без хардкода пользовательских параметров.
- Проверка: pytest, fault probes для критических тестов и ffprobe smoke validation.

## Приоритет решений

1. Неизменность слов пользователя.
2. Качество синхронизации.
3. Стабильность и восстановимость pipeline.
4. Качество instrumental.
5. Читаемость и внешний вид.
6. Скорость.
