# ТЗ v2 — локальный генератор karaoke MP4

Статус: подтверждено пользователем 2026-09-04.

## Цель и аудитория

Создать локальный инструмент для владельца MacBook Pro на Apple Silicon, который получает ровно два пользовательских файла — оригинальную песню `song.mp3` и окончательный текст `lyrics.txt`, — автоматически синхронизирует каждое пользовательское слово с распознанным вокалом и создаёт готовое karaoke-видео MP4.

Продукт продаёт технологию обработки пользовательских файлов, не содержит каталога музыки, не скачивает треки или тексты и не публикует результаты.

Главный инвариант: приложение MUST сначала распознать реально спетые слова в оригинальной песне, затем глобально сравнить эту ASR-последовательность с `lyrics.txt`. Финальные слова MUST происходить только из `lyrics.txt`, а их временные границы — из анализа аудио. Распознавание не вправе менять, исправлять, добавлять или удалять слова пользователя.

## Пользовательские сценарии

1. Пользователь выбирает оригинальный MP3 и UTF-8 TXT, запускает одну CLI-команду и получает `karaoke.mp4`, `karaoke.ass`, `alignment.json` и промежуточные файлы.
2. По умолчанию приложение пытается отделить вокал и использует instrumental в видео. При недоступности separation синхронизация продолжается по оригиналу, а режим аудио явно переключается на original с предупреждением.
3. Пользователь меняет оформление или вручную правит `alignment.json`, запускает только render и не повторяет ML-этапы.
4. Локальный Web UI предоставляет те же базовые действия: загрузить MP3 и TXT, запустить генерацию, видеть текущую стадию и монотонный процент выполнения без перезагрузки страницы, скачать артефакты.

## Входит в MVP

- Официальный входной контракт: оригинальная песня MP3 и готовый текст TXT. Других источников контента нет.
- UTF-8, кириллица, латиница, смешанный текст, пустые строки как границы блоков.
- Детерминированная очистка секционных заголовков и типовых рекламных блоков скопированного lyrics с отдельным отчётом об исключённых строках.
- Сохранение регистра, `ё`, апострофов, дефисов и пунктуации в отображаемом тексте.
- Автоматические word-level timestamps с монотонным сопоставлением повторяющихся строк.
- WhisperX как основной backend: faster-whisper формирует базовую ASR-сетку, а фонемное выравнивание уточняет доступные границы, не удаляя базовые слова. Чистый faster-whisper остаётся быстрым fallback.
- Lyrics prompt, мягкий настраиваемый VAD и пользовательский timing offset от −1000 до +1000 мс.
- Явная маркировка неуверенных и интерполированных слов.
- ASS с плавным `\kf`-эффектом, текущей и следующей строкой, переносом длинных строк без разрыва слов.
- 1080p H.264/AAC MP4 с оригинальным или инструментальным аудио.
- Встроенный фон, не требующий третьего пользовательского файла.
- Кеш тяжёлых стадий по хешу входов и значимых настроек.
- CLI, минимальный локальный Web UI, Docker и нативный macOS-запуск.
- Понятные логи, диагностическая команда и unit/integration smoke tests без обязательной ML-модели.

## Не входит в MVP

- Аккаунты, платежи, облако, публикация и каталог песен.
- Автоматический поиск, скачивание или сохранение музыки и полного текста песни.
- Мобильное приложение и production-хостинг.
- Фонемная/послоговая разметка и обещание студийной точности без ручной проверки.
- Полноценный визуальный редактор waveform; JSON остаётся редактируемым контрактом.

## Поведение и крайние случаи

- Текст токенизируется по пробелам; display-форма остаётся неизменной, для alignment хранится отдельная нормализованная форма.
- Строки вида `[Куплет]`, `[Припев]`, `[Outro]`, заголовок песни и известные маркеры рекламных блоков MUST исключаться до ASR. Исходный TXT MUST сохраняться, а причины исключения MUST записываться в `lyrics_cleanup.json`.
- Очистка MUST NOT удалять обычные строки только из-за языка: смешанный русский/английский текст остаётся допустимым.
- `faster-whisper` MUST сначала получить слова из вокала вместе с временными метками. В режиме WhisperX фонемное выравнивание MUST заменить границы только сопоставленных ASR-слов и MUST сохранить исходные ASR-времена для остальных слов. Generate без распознанного совпадения MUST завершаться ошибкой; равномерное распределение lyrics без анализа песни запрещено.
- Очищенный текст MAY передаваться ASR как `initial_prompt`, но MUST NOT становиться источником времён без аудиодоказательства.
- VAD MUST быть управляемым. Мягкий режим по умолчанию использует более низкий порог для тихого вокала; пользователь MAY отключить VAD для диагностического повторного запуска.
- Распознанные слова сопоставляются с пользовательскими глобальным sequence alignment в стиле usersync. Порядок времён строго не убывает, поэтому одинаковые строки не попадают в один момент.
- Aligner MUST поддерживать объединение и разделение соседних токенов, например `никогда ↔ ни когда`, без подмены display-текста.
- Для прямого совпадения JSON MUST сохранять `asr_text` и `match_similarity`, чтобы было видно, какое слово из песни послужило временным доказательством.
- Не найденное слово остаётся в результате с `aligned=false`, `confidence=0` и временем, интерполированным между соседями (`alignment_source=interpolated`).
- Если нет ни одного распознанного слова, обычный generate завершается понятной ошибкой; явно выбранный диагностический backend `uniform` допускается только для smoke/demo.
- Строки, не помещающиеся в безопасную ширину, делятся на визуальные строки по словам.
- ASS-рендер MUST применять пользовательский `timing_offset_ms` ко всей подсветке; отрицательное значение означает более раннюю подсветку. Допустимый Web/CLI-диапазон: −1000…+1000 мс.
- Рендер проверяет наличие FFmpeg с фильтром `ass`. На Homebrew приоритет имеет keg-only `ffmpeg-full`; обычный FFmpeg без libass отвергается с точной инструкцией.
- Любая стадия пишет атомарный артефакт; частичный `alignment.json` сохраняется, когда восстановление возможно.

## Данные, роли, приватность и интеграции

- Одна локальная роль: владелец файлов.
- Все входы, модели, кеш и результаты остаются на машине пользователя.
- Сеть нужна только при первоначальной установке пакетов/ML-моделей.
- Интеграции: локальные исполняемые `ffmpeg`/`ffprobe`, опциональные Python-пакеты `faster-whisper`, `whisperx`, `demucs`.
- Репозиторий создаётся приватным, если пользователь отдельно не запросил публичный.

## Критерии приёмки

Команда

```bash
karaoke-gen --audio song.mp3 --lyrics lyrics.txt --output result
```

без ручной переклейки создаёт открываемый `result/karaoke.mp4` с аудио и синхронной подсветкой слов, а также `karaoke.ass`, `alignment.json`, `processed_lyrics.txt`, `lyrics_cleanup.json` и метаданные кеша.

Дополнительно:

- все display-слова в JSON и ASS происходят только из `lyrics.txt`;
- заголовки секций и рекламный блок не попадают в ASS, а перечисляются в `lyrics_cleanup.json` с исходными номерами строк;
- `alignment.json` содержит фактически распознанный `asr_text` отдельно от пользовательского `text`, а также числа распознанных, сопоставленных и интерполированных слов;
- тест с `тибя` в ASR и `тебя` в TXT сохраняет в караоке `тебя`, но использует аудиотайминг распознанного слова;
- тест `никогда ↔ ни когда` использует общий реальный аудиоинтервал, а не равномерный timing;
- generate без единого совпадения ASR с lyrics завершается понятной ошибкой;
- repeated lines и timings монотонны;
- unit tests покрывают parser, нормализацию, кириллицу, пунктуацию, повторения, интерполяцию, ASS и перевод времени;
- smoke test создаёт MP4 без скачивания ML-модели;
- `karaoke-gen render --alignment ...` не запускает ASR/separation;
- Web UI после `Generate karaoke` немедленно показывает индикатор 0–100%, текущую стадию и результат или понятную ошибку;
- Web UI позволяет выбрать backend и модель, управлять VAD и менять timing offset от −1000 до +1000 мс;
- на Apple Silicon нет обязательной CUDA-зависимости, CPU fallback документирован;
- Docker-образ содержит FFmpeg с libass, но Docker не является единственным способом запуска.

## Предположения, риски и открытые вопросы

- Автоматическая синхронизация музыки не гарантирует frame-perfect результат: адлибы, перекрывающиеся голоса и неверный/неполный текст требуют правки JSON. Архитектура это допускает без повторного ML-запуска.
- WhisperX используется по умолчанию для точных word timestamps; его стандартный Mac-путь — CPU/INT8, MPS не считается обязательным. Первый запуск для нового языка загружает отдельную фонемную модель и занимает больше времени.
- Исходный Demucs больше активно не развивается; поэтому separator изолирован интерфейсом и по умолчанию может быть отключён. В будущем backend можно заменить на BS/MelBand-Roformer.
- Качество instrumental ниже исходной фонограммы и зависит от модели.
- Полный текст и аудио коммерческих песен пользователь обязан предоставить сам на законном основании. Тестовый репозиторий использует синтетический/public-domain материал.
- Открытый продуктовый вопрос после MVP: нужен ли встроенный waveform-редактор. Сейчас контрактом служит `alignment.json`.

## План реализации

- Python 3.11/3.12, пакет `karaoke_generator`, dataclasses/Pydantic-совместимый JSON.
- Независимые стадии: preprocess → optional separation → ASR оригинального вокала → WhisperX refinement → usersync-style sequence alignment с TXT → interpolate → ASS → FFmpeg render.
- Backends: `whisperx` (default), `faster-whisper` (быстрый fallback), `uniform` (explicit demo/test only).
- Рендер: FFmpeg `gradients`/background input + libass `ass` filter + H.264/AAC.
- CLI: стандартный `argparse` с командами generate/render/doctor/web; `karaoke-gen --audio ...` остаётся короткой формой generate.
- Web: FastAPI/uvicorn как optional extra поверх того же pipeline.
- Конфигурация: YAML с override из CLI, без хардкода пользовательских параметров.
- Проверка: pytest, fault probes для критических тестов и ffprobe smoke validation.

## Приоритет решений

1. Неизменность слов пользователя.
2. Качество синхронизации.
3. Стабильность и восстановимость pipeline.
4. Качество instrumental.
5. Читаемость и внешний вид.
6. Скорость.
