# Отчёт: перенос и происхождение таймингов слов

Дата: 6 сентября 2026. Ветка: `improve/word-timing-accuracy`. Baseline: `350088c8e904de533fdac818514038cd3d724076`. Отчёт первого этапа сохранён вместе с реализацией.

Это отчёт первого этапа. Последующие реальные ML-прогоны, найденные дефекты и контрольные видео описаны в [отчёте проверки без эталонов](timing-stability-report.md); ограничения ниже отражают состояние до этих прогонов.

Доступная без песен часть ТЗ реализована и проверена. **Улучшение акустической точности на реальном вокале не доказано:** размеченного корпуса нет, C на песнях не измерен, сравнение моделей и калибровка score не выполнены.

## Изменения

- ASS использует абсолютные `\kt` и длительность `\kf` между независимо округлёнными start/end. Пауза не растягивает заливку. Отрицательное начало не перезапускает уже прошедшую часть эффекта. Переносы и preview используют канонические времена слов.
- Default новых запусков — offset 0 мс. Явные YAML-значения сохраняются. CLI `render` принимает offset override; фактическое значение видно в логе, Web и диагностике.
- Schema 3 читает версии 1/2. `words[].start/end` остаются каноническими. История хранит ASR-границы/confidence, кандидата/score уточнения, источник, причины отказа и коррекции пересечений с дельтами. Ручная правка канонических времён не отменяется при чтении. Неизвестные исторические сведения не заполняются догадками.
- WhisperX получает отдельные ограниченные окна из одной ASR-последовательности, контекст по умолчанию 0,3 с, максимум окна 20 с. Проверяются конечность, положительность, аудио, окно, score и соседние якоря. Отказ сохраняет ASR и причину; отсутствие текстового соответствия — интерполяцию; отсутствие всех совпадений — ошибку.
- Составные соответствия используют доступные символьные границы. Разбиение по длине текста явно помечается приблизительным. Исправлено также растягивание отдельной сетки при соответствии «два слова → два слова».
- Отдельные ASR/refinement-кеши учитывают фактический WAV, настройки, версии алгоритмов/пакетов и доступную ревизию модели. Смена модели/окна не повторяет ASR. Offset и оформление не инвалидируют ML; ручные правки сохраняются при повторном использовании mapping.
- Подготовка и renderer задают начало по декодированным сэмплам. Диагностика хранит stream start, частоты, длительности, доступные sample counts; сравнивает сигнал в трёх участках оригинала/подготовки, суммы stem и выходного MP4. Тишина и недостаточная корреляция дают `inconclusive`; доказанный сдвиг — ошибку.
- Web различает «Сопоставление текста» и отсутствие измеренной точности времени. Показывает модели, offset и источники таймингов.
- Добавлен runner эксперимента на замороженных ASR/WAV и evaluator с nearest-rank, бесконечными ошибками отсутствующих границ, покрытием, результатами песен/сложных случаев и порогами приёмки.

## Baseline и проверки

Исходный набор: 26 тестов прошли. После реализации: 57 тестов прошли, включая реальный FFmpeg/libass, кадры MP4, декодированный AAC, MP3 с ненулевым stream start, совместимость JSON, кеши, полный generate/rerender и тестовый запуск runner сравнения.

Среда: macOS 26.5.2 arm64, Python 3.12.2, FFmpeg 9.0.1, libass 0.17.5; faster-whisper 1.2.1, WhisperX 3.8.6, CTranslate2 4.8.2, torch/torchaudio 2.8.0, transformers 4.57.6, NumPy 2.5.2. Тесты модели используют управляемые ответы: настоящая ML-генерация на пользовательской песне не выполнялась.

Синтетический клип: 30 fps, три слова `MMMM`, start/end `[0.10, 0.50]`, `[0.90, 1.40]`, `[1.70, 2.30]`. Есть паузы 400 и 300 мс. В исходном WAV 48 кГц — воспроизводимые шумовые аудиомаркеры. Проверяются подготовка 44,1 кГц и декодированный MP4 на контрольной частоте 16 кГц. Визуальное начало определяется появлением >1% активных пикселей слова, завершение — ≥99%; это измерение рендера, не акустической разметки.

Ошибки таблицы считаются относительно канонических границ с указанным offset, обрезанных у нуля. Во всех вариантах положение трёх аудиомаркеров после подготовки и AAC: 0 сэмплов сдвига на 16 кГц. **Акустическая JSON-сетка B0/B1/B2 одинаковая.**

Проверка 250 дробных интервалов подтверждает ≤5 мс ошибки каждой абсолютной ASS-границы без накопления. MP4 исправленных вариантов укладывается в заявленный допуск одного кадра +10 мс. Просмотр кадра на 0,7 с подтверждает завершённую заливку первого слова и ожидание следующих.

Скрипт `scripts/verify_timing_faults.py` подтвердил достижимость генератора и чувствительность тестов к трём нарушениям: включение паузы в заливку, перезапуск отрицательного начала, принятие низкого score. Все четыре пробы обнаружены, после каждого восстановления тесты проходят. Пробы выполнены в отдельной временной копии, точные diff и логи сохранены.

## Непроверенная часть и ограничения

Нет корпуса ≥5 песен/15 фрагментов/500 слов с отдельной приёмочной группой ≥3 песен/300 однозначных слов. Поэтому нет реальных median/P90 начала/конца, signed bias, покомпозиционной регрессии и подтверждения снижения P90 на 30%.

`bond005/wav2vec2-base-ru` остаётся default. Сравнение с `jonatasgrosman/wav2vec2-large-xlsr-53-russian`, необязательным `bond005/wav2vec2-large-ru-golos`, окнами и score-порогами требует фиксированного корпуса. Совместимость третьей модели не проверена. Default score 0,05 — некалиброванный sanity-фильтр; более высокий score сам по себе не доказывает точность границы.

Новая оконная обработка проверена на синтетических/управляемых ответах API, а не на настоящем пении. Проверка суммы stem не заменяет акустическую разметку и может дать `inconclusive`. Проверки аудио используют NumPy; без него диагностика PCM явно недоступна. Новые кеши занимают место и автоматически не очищаются. Ревизия модели неизвестна, если её нельзя определить из локального кеша.

Следующий этап: зафиксировать разметку и разделение песен, сравнить модели на tuning, зафиксировать параметры и выполнить независимую акустическую приёмку при offset=0. Архитектурные контракты остаются draft до отдельного принятия пользователем.
